# 软件工程实战与理论大作业：基于 GitFlow 与 GitHub 的团队协作演练

#### 一、 项目背景与架构规范

某软件公司正在开发一款名为 **mall-system** 的电商促销系统。团队采用标准的 **GitFlow** 协作模式，集中在同一个 GitHub 共享仓库中进行开发。

##### 1.1 团队角色定义

- **项目经理 / 技术负责人（PM-Bob）**：负责项目整体仓库搭建、初始分支创建、权限配置、代码审核（Code Review）、合并策略决策、预发布分支创建及版本发布。
- **开发人员（Dev-Alice）**：负责日常需求开发（如优惠券计算模块）、修复反馈问题、解决代码合并冲突及提交 Pull Request。

##### 1.2 分支架构规范

1. **main（生产主干）**：存放随时可发布的生产环境稳定代码。受到严格保护，禁止直接 Push。

2. **develop（集成开发分支）**：团队日常功能集成的核心分支。同样受保护，仅允许通过 Pull Request 合并。

3. **feature/\***（特性分支）：开发人员完成具体需求的分支（如 `feature/coupon-calc`），以斜杠分类，属于独立平级分支。

4. **release/\***（预发布分支）：用于发版前的打包、版本号修改及回归测试（如 `release/v1.0.0`）。

#### 二、 演练任务与题目要求

请根据以下五个阶段的业务发展情景，分别扮演 **PM-Bob** 和 **Dev-Alice**，写出具体的 Git 终端操作命令或 GitHub 网页端的配置与点击路径。

##### 阶段一：仓库初始化、初始分支创建与安全规则配置（PM-Bob 统筹）

1. **【远程仓库创建与本地关联】** PM-Bob 需要在 GitHub 上新建一个名为 `mall-system` 的共享仓库，并在本地初始化项目骨架代码，将其推送到远程仓库的默认 `main` 分支
2. **【开发主干 develop 分支创建】** 项目刚启动时，PM-Bob 需要基于 `main` 切出一个团队公共的开发主干分支 `develop`，并推送到远程仓库。

##### 阶段二：任务认领与本地特性开发（Dev-Alice 负责）

1. **【特性分支切出与初始化】** Alice 接到了“优惠券计算”需求的开发任务。她需要克隆仓库，确保本地 `develop` 分支代码最新，并从中切出一个名为 `feature/coupon-calc` 的独立特性分支（**注意：项目启动时 PM 无需预先创建此分支**）。
2. **【代码提交与远程推送】** Alice 在本地完成开发，提交了变更后，准备将该特性分支首次推送到 GitHub 远程仓库。

##### 阶段三：模拟并发开发与代码冲突解决（Dev-Alice & PM-Bob 协同）

1. **【制造并发冲突场景】** 在 Alice 准备将代码集成到主干前，PM-Bob 在 `develop` 上直接推送了一次修改，修改了与 Alice 相同的文件的同一行代码，导致远程 `develop` 产生并发更新。
2. **【发起 Pull Request】** Alice 登录 GitHub 提交 PR，请求将 `feature/coupon-calc` 合并到 `develop` 分支，指派Bob作为审查人。
3. **【本地解决分支冲突与更新 PR】** PR 提示 **"Can't automatically merge"**。Alice 需要在本地拉取最新 `develop` 代码并解决冲突。

##### 阶段四：Code Review 与功能合并（PM-Bob 统筹 & Dev-Alice 协同）

1. **【代码审查与修改反馈】** PM-Bob 收到 Review 请求，在代码审查时发现 Alice 的代码中硬编码了测试密钥，并且缺失单元测试。
2. **【最终合入策略选择与分支清理】** 修复通过后，PR 变为绿色可合并状态。为了保持 `develop` 历史记录整洁干净，避免大量琐碎的提交历史污染主干：

##### 阶段五：预发布与生产发布（PM-Bob 统筹）

1. **【切出 Release 分支】** `develop` 分支集成完毕，PM-Bob 准备进行发版准备，从 `develop` 分支切出 `release/v1.0.0` 预发布分支，修饰版本号并推送到远程。
2. **【生产合并、版本打标与发布 Asset】** 在预发布分支测试通过后，PM-Bob 需要将 `release/v1.0.0` 分别合并至生产分支 `main` 和开发分支 `develop`，在 `main` 上打版本 Tag 并推送到远程，最后在 GitHub 上发布官方 Release。
